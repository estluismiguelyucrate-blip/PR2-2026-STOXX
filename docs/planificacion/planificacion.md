# Planificación del proyecto

Esta página reúne las fuentes de planificación existentes para evitar mantener dos cronogramas como si fueran una única línea base.

## Fuentes vigentes

- [Gantt original editable](../gantt/Diagrama_Gantt_tabla.xlsx) y [vista PNG](../gantt/Diagrama_Gantt.png): línea base académica del proyecto, tareas, responsables y fechas registradas en el libro.
- [Lectura y seguimiento del Gantt](../gantt/seguimiento.md): transcribe hitos y señala fechas/estados que el equipo debe revisar.
- [Cronograma de cierre de madurez](CRONOGRAMA_MADUREZ.md) y [CSV editable](CRONOGRAMA_MADUREZ.csv): propuesta separada para cerrar la revisión del MVP.
- [Riesgos y responsabilidades](../gestion/RIESGOS_Y_RESPONSABILIDADES.md): responsables de seguimiento y mitigaciones.

## Hitos y dependencias

| Hito | Entregable | Responsable principal | Dependencia / condición |
|---|---|---|---|
| H1 — Definición del MVP | Alcance y criterios de aceptación revisados. | Equipo completo; coordinación de desarrollo. | Confirmar que el alcance refleja la aplicación web actual. |
| H2 — Validación funcional | Casos manuales ejecutados con resultado, fecha y evidencia. | QA/documentación con apoyo de desarrollo y análisis. | Preparar datos ficticios y un entorno disponible. |
| H3 — Corrección de defectos | Defectos críticos corregidos o con limitación y plan documentados. | Desarrollo principal; validación de QA. | Resultados de H2. |
| H4 — Revisión de presentación | Documentación, Gantt, enlaces y presentación revisados. | Equipo completo. | H1–H3 y confirmación del equipo/docente de fechas aplicables. |

Las fechas propuestas y los estados detallados se mantienen en sus documentos fuente. No se consideran aprobados por esta página; el equipo debe actualizarlos y confirmar responsables/fechas antes de presentar.

## Cadencia de seguimiento

En cada reunión, registrar trabajo terminado con evidencia, tareas retrasadas, bloqueos, decisiones, responsable y fecha de la siguiente acción. Usar issues de GitHub para defectos y trabajo técnico; si el equipo usa otro mecanismo acordado, mantener allí el vínculo al issue o tarea.
