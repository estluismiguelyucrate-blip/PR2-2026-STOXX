# Acuerdos de trabajo

**Estado:** propuesta para revisión y aprobación del equipo. No representa acuerdos aprobados hasta que los integrantes los confirmen.

## Propuesta

1. Registrar tareas, defectos y decisiones en GitHub Issues o en el mecanismo equivalente que el equipo acuerde.
2. Asignar un responsable y una fecha objetivo a cada tarea; registrar bloqueos y dependencias.
3. Usar ramas para cambios y pull requests hacia `main`, con revisión de otro integrante cuando el calendario lo permita.
4. Mantener commits pequeños y descriptivos, vinculando el issue relacionado cuando exista.
5. Ejecutar las pruebas automatizadas para cambios de código y registrar las pruebas manuales con resultado y evidencia en `QA/`.
6. No incluir secretos, información real de clientes ni capturas con credenciales.
7. Actualizar README, requisitos, arquitectura, modelo de datos o planificación cuando cambie la solución o el plan.

## Registro de aprobación

- **Fecha de revisión:** pendiente
- **Integrantes que aprobaron:** pendiente
- **Cambios acordados:** pendiente
